# ReviewOps 사용 안내

ReviewOps는 프로젝트의 리뷰, 스크린샷, 파일과 Codex 작업을 컴퓨터에서 관리하는 앱입니다. ReviewOps 서버와 계정은 필요하지 않습니다. 프로젝트는 그룹 안에서 관리하며, 각 프로젝트에 로컬 폴더 또는 SSH 호스트를 연결합니다.

## 설치

Windows 10/11 x64와 macOS 13 이상에서 사용할 수 있습니다.

### Windows

1. [최신 릴리스](https://github.com/season-framework/reviewops-local/releases/latest)에서 `ReviewOps-<버전>-windows-x64.exe`를 내려받습니다.
2. 설치 파일을 실행하고 설치 폴더를 선택합니다. 사용 중인 Windows 계정에 설치됩니다.
3. 시작 메뉴 또는 바탕 화면의 ReviewOps를 실행합니다.

Windows 설치 파일에는 코드 서명이 포함되지 않습니다. 앱을 업데이트하거나 제거해도 프로젝트 자료는 보관합니다.

### macOS

1. [최신 릴리스](https://github.com/season-framework/reviewops-local/releases/latest)에서 Mac에 맞는 DMG를 내려받습니다.
2. Apple Silicon Mac은 `arm64`, Intel Mac은 `x64` 파일을 선택합니다.
3. DMG를 열고 ReviewOps를 Applications로 드래그합니다.
4. 응용 프로그램 폴더에서 ReviewOps를 실행합니다.

macOS 13 이상이 필요합니다. Apple 공증은 포함하지 않습니다. 처음 실행할 때 macOS가 차단하면 [Apple의 실행 안내](https://support.apple.com/ko-kr/102445)를 따르십시오.

## 프로젝트 연결

1. **그룹**에서 그룹을 만들거나 선택합니다.
2. 그룹 안에서 **프로젝트 등록**을 선택합니다.
3. 접속 방식에 **로컬 폴더** 또는 **SSH 호스트**를 지정합니다.
4. SSH 호스트는 사이드 메뉴의 **호스트관리**에 먼저 등록합니다. 프로젝트에서 저장된 호스트와 서버 작업 폴더를 선택합니다.
5. 프로젝트 **설정**에서 웹사이트 주소, 화면 크기와 에이전트 설정을 변경합니다.

로고와 상단 탭 줄의 빈 공간을 드래그하면 창을 이동합니다. 홈을 제외한 탭은 드래그하거나 **Alt+Shift+←/→**로 순서를 바꿉니다.

## 리뷰와 첨부

프로젝트에서 리뷰를 등록하고 설명, 상태, 분류와 우선순위를 지정합니다. 기본 분류는 버그, UX, 콘텐츠, 성능, 접근성, 보안, 기타입니다. 분류 옆 **+**를 누르면 이름을 입력하여 새 분류를 추가할 수 있습니다. 추가한 분류는 다른 리뷰에서도 선택할 수 있으며 백업과 복원에도 포함됩니다. 스크린샷, 로그와 파일을 함께 첨부할 수 있습니다. 뷰어에서 캡처하거나 작업이력 입력창의 **+**에서 자료를 추가합니다. **검토대상**에서 요소를 지정하면 선택한 요소에 테두리가 유지됩니다. **선택 요소로 이동**으로 해당 위치를 다시 표시하고 **요소 표시 해제**로 테두리를 지울 수 있습니다.

작업이력에는 대화와 에이전트 진행 내용을 함께 표시합니다. 작업지시서 ZIP에는 요청, 로그, 스크린샷, 작업이력과 첨부 자료를 묶어 저장할 수 있습니다.

뷰어는 웹사이트의 쿠키와 로그인 상태를 별도로 유지합니다. 4K, FHD, HD, 태블릿, 모바일 또는 직접 입력한 화면 크기를 사용할 수 있습니다. 사용자 입력 숫자는 Enter를 누르거나 입력창을 벗어날 때 적용합니다.

## Codex 작업

로컬 작업은 이 컴퓨터의 Codex CLI로, SSH 작업은 선택한 서버의 Codex CLI로 실행합니다. 작업할 환경에 Codex를 설치하고 로그인해야 합니다. **프로젝트 → 설정 → 에이전트**에서 실행 파일, 모델, 작업 지침을 지정합니다.

앱은 시작할 때 로컬과 등록된 SSH 호스트의 모델 목록, 지원하는 추론 수준과 기본 설정을 수집하고, 기본 1시간마다 다시 수집합니다. 리뷰의 **에이전트**에서는 저장된 목록을 바로 사용하며 호스트에 다시 접속하지 않습니다. **호스트관리**에서 호스트별 목록과 마지막 수집 시간을 확인하고 직접 다시 수집할 수 있습니다. 수집에 실패하면 마지막 성공 목록을 유지합니다. **설정 → 자동 확인**에서 수집 주기를 바꿀 수 있습니다. 저장된 목록이 없으면 **프로젝트 → 설정 → 에이전트 → 모델 직접 등록**에서 모델 ID, 표시 이름, 추론 수준을 직접 등록할 수 있습니다. 등록한 목록은 프로젝트 연결 설정과 함께 저장하며 백업에도 포함합니다.

리뷰의 **에이전트**에서 요청과 첨부 자료를 전송합니다. 첫 요청에 작업 지시서, 스크린샷과 로그를 자동으로 포함하고, 그다음 요청부터는 텍스트만 보냅니다. 자료가 더 필요하면 **+**에서 직접 추가하십시오. 모델 목록 수집에 실패하면 저장된 목록을 유지하며, 오류는 **설정 → 자동 확인**에서 확인할 수 있습니다. 작업이 시작되면 리뷰 상태가 **진행**으로 바뀝니다. 응답의 파일 링크는 실행 당시 연결과 작업 폴더에서 엽니다.

각 요청은 선택한 모델·추론 수준, 실행에 전달한 값, 실행 프로그램이 알려준 실제 사용값을 구분하여 보관합니다. 이후 설정을 바꾸거나 다시 실행해도 이전 기록을 덮어쓰지 않습니다. 값이 없는 과거 기록에는 나중에 선택한 설정을 채우지 않습니다. 자세한 값, 요청·실행 ID와 원본 로그는 **더보기**에서 엽니다.

**요청문 복사**와 **응답 복사**는 원문을 복사하며 성공·실패를 표시합니다. 작성 중인 응답을 복사하면 그때까지 작성된 내용만 포함합니다. 실행 중에는 대화 하단에 마지막 작업을 표시하며, 누르면 저장된 실행 기록이 열립니다. 긴 목록은 내부에서 스크롤할 수 있습니다. 이전 내용을 읽던 중에는 위치를 유지하며 **최신 내용으로 이동**으로 새 출력에 이동합니다.

실행 중에도 같은 작성창에서 다음 요청을 입력하고 **대기 목록에 저장**할 수 있습니다. 저장과 실행은 별도 동작이며, 대기 요청의 실행 버튼을 눌러야 시작합니다. **이어서 요청**은 같은 대화에 연결하고, **새 대화로 시작**은 대화를 새로 만듭니다. 대기 요청 수정과 이전 요청 가져오기를 사용해도 다른 초안을 보존합니다. 상세 실행 설정과 연결 정보는 작성창의 **더보기**에서 엽니다.

실행 명령은 `codex exec --dangerously-bypass-approvals-and-sandbox`입니다. 작업은 선택한 계정의 권한으로 실행하며 별도 샌드박스나 승인 절차를 추가하지 않습니다.

## 계정과 호스트

**계정관리**에서 Codex 계정별 로그인, 사용량과 통계를 관리합니다. 계정별 저장 폴더를 사용하므로 기본 Codex 로그인 파일은 변경하지 않습니다. 인증 정보는 파일로 저장하고 키체인을 사용하지 않습니다. 기존 계정 정보를 가져올 때 키체인에만 있는 인증 정보는 복사하지 않으며 다시 로그인해야 합니다.

**호스트관리**는 `~/.ssh/config`와 포함된 SSH 설정을 사용합니다. 저장한 호스트를 여러 프로젝트에 연결할 수 있습니다. 파일 탐색, 업로드, 다운로드, 이름 변경, 이동, 삭제와 원격 Codex 관리를 지원합니다.

## 설정과 업데이트

설정의 언어 선택 목록에서 언어 이름을 검색하여 화면 언어를 바꿀 수 있습니다. 영어, 한국어, 일본어, 중국어 간체·번체, 스페인어, 프랑스어, 독일어, 브라질 포르투갈어, 이탈리아어, 러시아어, 베트남어를 지원합니다. 일부 기술 메시지는 영어로 표시됩니다. 작성한 내용과 외부 웹사이트는 번역하지 않습니다.

macOS 앱은 자동 확인이 켜져 있으면 시작 즉시 업데이트를 확인하고, 실행 중에는 기본 10분마다 확인합니다. **설정 → 자동 확인**에서 확인 주기를 바꿀 수 있습니다. 설정에서 자동 확인을 다시 켤 때도 즉시 확인합니다. 공개 GitHub Releases를 사용하므로 GitHub 계정이나 토큰을 앱에 입력할 필요가 없습니다. 새 버전이 있으면 왼쪽 사이드 메뉴 하단에 알림이 표시됩니다. 알림을 누르면 다운로드와 설치 후 앱을 다시 시작합니다. 설정 화면에서도 같은 기능을 사용할 수 있습니다. 파일을 검사한 뒤 앱을 교체하며 프로젝트 자료는 유지합니다.

SSH 에이전트 작업은 앱이 종료되어도 서버에서 계속 실행하며, 앱을 다시 시작하면 같은 작업의 출력과 결과를 읽습니다. 서버에 bash, nohup, setsid가 필요합니다. 로컬 작업, 터미널, 로그인과 파일 전송은 완료한 뒤 업데이트하십시오.

SSH 작업 유지는 1.2.2 이후 버전에서 시작한 작업부터 적용합니다. 이전 버전에서 실행한 작업은 완료한 뒤 1.2.2를 설치하십시오.

작업이력의 사진·문서·로그는 본문 아래 첨부 버튼으로 표시합니다. 버튼을 누르면 팝업에서 내용을 열고 파일을 내려받거나 삭제할 수 있습니다.

Windows의 정식 업데이트는 최신 설치 파일을 내려받아 앱을 종료한 뒤 다시 설치합니다. 정식 버전의 업데이트 방식은 유지합니다. Season AI 연결은 Windows에서 지원하지 않습니다. 호스트관리의 SSH 연결은 키 인증을 사용합니다.

### 테스트 버전 받기

**설정 → 자동 확인 → 앱 업데이트**의 **테스트 버전 받기**를 켜면 정식 출시 전 최신 버전을 확인할 수 있습니다. 기본값은 꺼짐입니다. 개발 PC와 다른 PC에서도 테스트 설치 파일을 받을 수 있습니다. 테스트 배포는 최신 빌드 하나만 유지하며, 새 빌드가 나오면 이전 테스트 설치 파일을 교체합니다.

설치된 버전과 받을 버전은 따로 표시합니다. **자세히 보기**에서 빌드 번호·커밋·생성 시간을 읽고 **버전 정보 복사**로 복사할 수 있습니다. macOS에서는 기존 업데이트 동작으로 설치합니다. Windows에서는 **설치 파일 받기**로 내려받고 검사한 뒤 **설치 파일 열기**를 선택합니다. 앱은 자동으로 종료되지 않으므로 앱을 닫고 설치 안내에 따라 진행하십시오.

확인·다운로드 중에도 선택을 바꿀 수 있습니다. 선택을 해제하면 이후 정식 업데이트를 확인하며, 설치된 앱을 이전 버전으로 바꾸지 않습니다. 프로젝트 자료를 삭제하거나 이전 백업으로 자동 교체하지도 않습니다. 1.2.10에서 저장한 자료는 1.2.9에서 열 수 없으므로, 이전 앱으로 돌아갈 필요가 있다면 업데이트 전에 백업하십시오.

## 자료 보관과 삭제

macOS 저장 위치는 `~/Library/Application Support/ReviewOps Local/`, Windows 저장 위치는 `%APPDATA%\ReviewOps Local\`입니다. 이전 설치의 자료를 계속 사용하도록 기존 폴더 이름을 유지합니다.

**설정 → 백업 파일 저장**에서 프로젝트 자료와 첨부를 JSON으로 백업합니다. SSH 비밀번호, 키 암호, Codex 로그인 정보와 외부 사이트 쿠키는 이 백업에 포함하지 않습니다. 전체 자료를 옮기려면 앱을 종료한 뒤 데이터 폴더를 보관합니다.

그룹과 프로젝트를 삭제하려면 이름을 입력해야 합니다. 그룹 삭제 시 내부 프로젝트, 리뷰, 작업이력과 첨부도 삭제합니다. 프로젝트 삭제 시 해당 리뷰와 첨부 자료를 함께 삭제합니다. SSH 호스트와 Codex 계정은 별도로 관리합니다.

문제는 [Issues](https://github.com/season-framework/reviewops-local/issues)에 앱 버전, 운영체제 버전, 재현 순서를 적어 등록하십시오. 토큰, 비밀번호, 개인 키와 실제 프로젝트 자료는 포함하지 마십시오.
