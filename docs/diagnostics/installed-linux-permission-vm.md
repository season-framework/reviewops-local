# One original Linux VM for the installed-app permission diagnostic

This source adds an import-safe Node owner and inert guards. It does not register or dispatch a workflow. No actual tool, seed, key, runtime installation, guest or app result is supplied by the source. Use `unboundRequest()` from the guard module as a data template: actual pins, runner/run, versioned machine and deadlines remain null, and its authority is false.

The owner consumes the accepted R3 supply from run 41806165323, product source `2a1e9f166e61eb3a30148ea624b4bb921c8ebd6a`, and a separately accepted private QEMU installation and packaged R41 ARM app (1.4.1 / 41001 / development 3). Its base is `34bf2ed064a93c709a2f6d00caa70ca444abca55`; all 438 old files must retain their bytes and modes. Only four diagnostic paths are added. No product, existing UI driver, release or supply workflow changes here.

Root must explicitly allow conditional one-use guest/UI derivation and maxima of one VM, one app and one powerdown; network acquisition authority must be false. There is no default true authority, arbitrary reconnect or self-approval.

## Actual setup, never an assumed ISO

Setup retains each original ssh-keygen/hdiutil/qemu-img child from creation. It records argv, PID, native exit/close, observed stdout/stderr EOF/close, fileback closure and byte pins. Output caps or observation failures never become success. A pending or uncertain original is held without signals, process adoption or another attempt.

Evidence saves are nonthrowing in original-process, QMP, SSH and HELD callbacks. The first persistence failure is retained in memory as a permanent failed verdict with sanitized error type/code; later successful saves cannot reset it. Further setup, remote requests, QMP queries and UI/VM starts are refused. Existing originals continue draining. The separately admitted ordinary powerdown/connection closure path remains available when its actual cleanup predicates hold. If the disk never recovers, durable output is not claimed; the original owner remains retained rather than throwing out of a callback or timer. Synchronous proof-file creation failure stays inside the owner's main try/finally and cannot be treated as an accepted handoff.

Create one ephemeral Ed25519 client key with an explicit argv and empty passphrase, never a user's agent/key. Keep the private key under vm-secrets; only its public wire key enters NoCloud data. Fixed local cloud-config creates locked-password non-root `rvqa` UID1001, disables password/root SSH, performs no apt/package/OAuth setup, and emits a nonce-bound public bootstrap marker on the original serial stream. The guest's actual host public key comes from its own fresh OpenSSH key; it is not guessed from a TCP port.

The fixed hdiutil `makehybrid` command writes ISO9660/Joliet with `cidata` volume name. A bounded in-memory parser then checks actual descriptors, both-endian extent fields, volume labels, exact three Joliet filenames and bytes (`user-data`, `meta-data`, `network-config`), and the same primary-namespace file extents. No mount, alternative ISO builder, overwrite or trusting exit0 alone. Source inspection does not yet prove the runner's hdiutil output is compatible; an unexpected namespace fails honestly before VM launch.

A new read-only copy of the accepted standalone QCOW base backs one disposable overlay. The accepted private qemu-img performs one `create` with explicit qcow2 backing format, then `info --output=json`; actual format, backing path and virtual size must match. The base and seed are rehashed after use. No base resize or substitute image is selected.

## Original QEMU, QMP and guest handoff

Port reservation is released once before launch; bind failure is final, not an alternate-port retry.

One explicit ID is outstanding; interleaved events are retained and wrong replies fail. Requests are never resent. Greeting/version/target and the nonce-tagged serial marker belong to this original. No readiness condition replaces its live handle.

After the marker the owner makes one SSH2 bootstrap connection with the ephemeral key and exact observed host key. Its ready timeout is a readiness boundary, not a VM or authentication retry. Fixed non-root controls create canonical0700 directories and leaf, transfer the exact genuine ELF and sealed witness over SFTP, verify guest size/SHA and identity, and invoke the genuine ELF `--version` once. There is no model generation, login or app-server warm-up in bootstrap. Actual codeHome has no auth.json/credentials.json. Original bootstrap channels, SFTP and client must close before UI handoff.

The transparent witness records argv/cwd/UID/effective HOME/CODEX_HOME/forbidden environment names outside the leaf and immediately execs the genuine ELF with unchanged environment/streams. ## Cleanup and honest failure

After UI starts, powerdown requires its actual bound result, same leaf restored0700, control connection closed, original app normal quit once/exit0/close/observed stdout-stderr EOF/close, and original UI child closure. A child exit or missing JSON alone never proves app absence. Before any UI attempt, a failed bootstrap can use the same authorized single ordinary powerdown only when explicit internal state proves zero UI attempts, no possible deny, and every owned bootstrap channel/client closed. No restoration is required for a leaf never denied. The failed verdict stays failed.

One QMP `system_powerdown` is allowed. Its reply only acknowledges; normal completion additionally requires a **post-request** `SHUTDOWN` with `guest:true` and `reason:guest-shutdown`, original QEMU exit0/close, complete observed streams/filebacks and QMP closure without protocol error. POWERDOWN, guest-reset/panic, EOF or another exit reason is insufficient. No QMP quit, second request, SSH poweroff, signal or workflow/VM retry is a fallback. Unknown app/bootstrap/process/QMP lifetime remains HELD. An independently observed abnormal terminal original can be reported closed and failed, never as successful normal poweroff.

Runtime deadlines are exact request inputs under bounded caps, not defaults silently extended after failure. Tool/driver deadlines, unexpected output and partial frames remain failures even if later cleanup succeeds. The result always preserves `nativeQAAccepted:false`; Root must review actual bytes, photos and combined evidence separately. This repeats QA-034-004 and adds zero formal IDs.

Upload only explicitly reviewed sanitized metadata, receipt/public pins, witness observations and whole-app photos. Never recursively upload privateRoot, private key, seed contents, overlay, guest HOME, sockets or raw private serial/tool filebacks. Do not delete unknown live resources to manufacture cleanliness. The implementation contains no downloads, signing, supply installation or global cleanup.

## v4 current-run live-tree correspondence

The input is the exact private runtime producer dictionary `{relative: {mode, type, bytes, sha256}}` for regular files, `{relative: {mode, type, target}}` for symlinks, and `{relative: {mode, type}}` for directories. Unknown fields/types, duplicate or noncanonical paths and undeclared directory parents are refused. JSON is capped at 8 MiB, entries at 20,000, total regular bytes at 1 GiB and each regular file at 512 MiB. Zero-byte regular data requires the exact empty SHA256; executable and authority/JSON pin admission remains nonempty. The actual R1 metadata (17,386 rows / 920,805,774 regular bytes) fits these bounds; that metadata is not itself a live observation in a later job.

Only an exact logical `/tmp/r34hhhh` to physical `/private/tmp/r34hhhh` relationship is allowed. The real root must be a current-user directory with mode 0700 and the same dev/inode/UID/mode/birth identity across the three reads. Each read enumerates with no-follow lstat, checks the exact entry set, permission mode, current UID and regular size/SHA, then enumerates and checks identities again. Every regular file is opened O_NOFOLLOW/O_NONBLOCK, matched to its pre-read lstat through fstat, read in bounded blocks to EOF and rechecked through FD/path and directory ancestors. Full directory observations detect owned-tree entry changes. Ancestor incarnation checks do not mistake unrelated entries in shared /private/tmp for replacement of that directory.

Symlinks are never opened as regular files or followed by traversal. Their literal relative targets must match, resolve finitely through declared members, and neither escape the private prefix nor cycle or dangle. Absolute targets are rejected even when spelled inside the prefix; no broadened alias or system-library exception applies to filesystem links. The reader has no write/repair/sign/cleanup operation. These finite before/after checks are not an atomic filesystem snapshot or a guarantee against every adversarial rename-and-restore schedule; no actual loaded-image claim follows.

A mismatch or read error permanently fails the diagnostic and blocks wider setup/launch/remote work. Already-owned streams continue to drain, and the separately admitted ordinary cleanup remains available. Reader failure records retain only a controlled guard code or I/O error code; evidence persistence uses the existing nonthrowing permanent-failure saver. No post-read is manufactured while the original is HELD.

The v4 inert checks use owned synthetic trees below 64 KiB per fixture, including healthy and empty data, changed bytes/mode/type, extra/missing entries, outside links/cycles, root recreation, a change during an opened read, and an injected EIO. An instrumented open seam proves the owned outside target is never opened. They do not extract real archives, invoke any private executable or launch a VM/SSH/app. Future runtime authority is still false.
