# Installed Mac application → owned Linux permission UI

This source-only manual diagnostic repeats **QA-034-004**. It does not change the product or add a formal QA ID. Runtime is blocked until separate actual supply, source and booted-guest Root acceptances and a one-operation UI authority are present. The prepare-supply workflow alone must not start this driver: archives are not an installed emulator, a booted guest or an accepted UI run.

The target is the actual R41 public ARM package, source `2a1e9f166e61eb3a30148ea624b4bb921c8ebd6a`, 1.4.1-dev-3/build 41001. One original packaged application, one private profile, the same real Linux guest/non-root account/owned inode and a genuine pinned Linux CLI are required. The outer controller owns the VM lifetime; this driver never boots, stops or signals it.

## Actual UI and observation scope

The driver registers only a private fixture through existing `service.save` and `project.save(serviceIds)` APIs. This supported fixture seam preserves the production ssh2 path and real host-key TrustDialog. It does not insert database rows, replace `connectConfig`, run a synthetic SSH server or fabricate a diagnostic DTO. The actual AgentSettings **environment inspection** button is used for all three result phases.

1. Trust bootstrap checks the real observed fingerprint and uses the actual trust dialog. This setup traffic is retained separately from the three manual result phases.
2. Set the existing private model-cache interval to 1440 minutes. Wait initial cache queries and original app SSH channels to close, then take a phase baseline. Model cache uses `/`; it must not be silently subtracted from a denied-folder CLI counter.
3. Normal `0700`: require the genuine CLI version and real login-required state. Accessible environment inspection also uses app-server configuration/model-list metadata. It is not an agent job or model generation, and no authenticated preflight is claimed.
4. Denied `000`: change only the already-admitted inode through a typed owned control operation, click the original UI button, and require real Bash exit 125 / Permission denied, installation/login unknown, folder guidance, no install-needed advice and no additional transparent-witness entries. Unrelated background entries fail the strict zero-entry condition rather than being hidden.
5. Restored `0700`: require the same version/path and unauthenticated state, unchanged genuine ELF/witness seals and no auth file. Save original whole-host PNGs for normal, denied and restored phases without editing their pixels. These are application content, not OS-window decorations.

A passive observer attaches only to actual app ssh2 clients for the exact owned endpoint. It forwards original methods/callbacks/results unchanged and records original channel output/close/EOF. Guest Bash/CLI PIDs are not host ChildProcess handles. The configured transparent witness records `args`, `cwd`, `uid`, `home`, `codeHome`, and forbidden-environment **names only**, then execs the actual sealed ELF without changing output or exit. Its path/hash is distinct from the ELF. No fabricated version, authentication or RPC answer is admitted.

## Binding contract

Use an external binding with `schema:1`, `phase:"ui"`, `scenario:"installed-linux-permission"`; product source/build are fixed while `harnessSource` must equal the actual manual workflow SHA. The source guard covers all 429 original files unchanged. Required actual pins are `preparedSupplyPin`, `preparedRootAcceptancePin`, `guestRootAcceptancePin`, `sourceGuardRootPin`, public ZIP, ASAR, executable, Node and this driver. Runtime dependency entry pins are checked before loading Playwright/ssh2.

The prepared Root acceptance must join the actual supply pin and product source. The separately created booted-guest acceptance must join the same supply pin, product source, exact `guest` record and `originalVMRetained:true`. The guest record includes the localhost endpoint, ephemeral key pin, real fingerprint, boot ID/kernel/non-root UID/EUID/machine, `/home/<user>`/its `.codex`, owned leaf device/inode/UID, genuine ELF seal/version and witness seal/log path. All these values must come from actual observations; null or sample values cannot authorize a run.

Guest controls are fixed source-authored Python scripts for status, deny and restore only. They check the original Linux identity/inode and file seals, use no subprocess, do not accept arbitrary shell strings, and preserve logs. The SSH private key is read only from its admitted private pin and is never serialized. Product credentials and SSH agents are not inherited. Node HOME/userData/CODEX_HOME are checked; native OS home is recorded independently. A short temporary profile is required for the Unix socket limit.

The explicit future invocation is:

```sh
node scripts/diagnostics/installed-linux-permission-ui.mjs --binding /absolute/actual-ui-binding.json --approval /absolute/ui-authority.json
```

The authority must have `approvedForOneInstalledLinuxPermissionUI:true`, the exact binding SHA, source/harness source, `maximumAppLaunches: 1` and `vmStartOrStopAuthorized:false`. This document supplies no TRUE authority or actual pins.

## Closure and limitations

The driver restores the same leaf before normal app quit, requires original app/launcher exit0 and observed stdout/stderr EOF/close, and closes its original control SSH connection. It never calls `app.close`, `app.exit`, process kill, PID adoption, VM shutdown or an automatic retry. Unknown launch ownership, channels, restoration or closure remains HELD with original evidence. The outer VM owner must wait for confirmed UI completion before its own reviewed normal poweroff.

The no-signal claim is driver-only. Unchanged production cleanup traps can signal their own process group. The witness observes permitted metadata entry points, not every internal CLI child or global network activity. OAuth, user credentials, model generation, a private production host and the entire original issue are outside this diagnostic. Existing Darwin UI and Linux SSH2 runs remain separate; their results are not combined into this run.

Pure inert guards import no product module, dependency, app, key or SSH server:

```sh
node --test tests/installed-linux-permission-ui.test.mjs
```
