The workflow requires that exact reviewed branch commit, native macOS ARM, pinned Node24.22.2, read-only repository permissions and checkout credentials disabled. The driver reads the current official [Apple Silicon download link](https://learn.chatgpt.com/docs/app), then permits one DMG request chain on `persistent.oaistatic.com`. Response bodies have firm retained-byte caps of 4 MiB for documentation and 1 GiB (1073741824 bytes) for the DMG, each with at most one additional consumed overflow byte and no retry. The 30-second documentation and 180-second DMG values are soft network budgets, not hard end-to-end deadlines. DNS resolution, per-address connection attempts and TLS negotiation precede the timer for the owned socket and can exceed those budgets. After TLS setup, the body loop checks the remaining deadline and uses socket timeouts; the final closure/deadline guard rejects timeout-induced EOF as success. Redirects remain within their allowlist, carry no authentication/cookies and never print rejected redirect values. Current mutable bytes are a new vendor cohort; an observed version-string match alone does not confirm the exact reporter artifact or environment; the URL does not establish version26.1027.30824.

The first diagnostic attempt stopped before the DMG body because the response declared more than its original 768 MiB cap; it did not launch the vendor CLI. A separate HEAD-only measurement at 2026-11-03 01:19:42 UTC reported HTTP 200 and Content-Length 833385246 (approximately 794.8 MiB), so this successor permits a firm 1 GiB cap. This current mutable HEAD observation is not the first response's exact size or a vendor-byte/cohort proof. Before validating a final DMG response's declared size or reading its body, the driver writes only status, declared Content-Length, ETag, Last-Modified, cap and `EOF=false` to `official-DMG-response.json`. That file is a pre-body snapshot; `official-DMG.json` separately records actual successful EOF and byte hash. No cookies, authentication headers or complete response headers are retained. A failure remains a failure and cannot trigger an automatic retry.

Only a new runner-owned temporary directory is used. The DMG is mounted read-only and checked by its owned mount/device identity. The original `Codex.app` or `ChatGPT.app` name is preserved when copying with resource metadata into a fresh private `~/Applications`. Unknown layouts/IDs, minimum-OS incompatibility, missing native arm64, invalid Apple-anchored signatures, unexpected OpenAI signing authority, different signing teams or changed bundle bytes stop the diagnostic. Nothing is renamed, repaired, re-signed, installed in `/Applications`, stripped of quarantine or granted OS permissions.

The C2 diagnostic reached a matching disk-image mount and reported `Writable=false`, `WritableMedia=false` and `WritableVolume=false`, but its validator required an absent `ReadOnlyVolume` field. That run remains failed, with detach unconfirmed; the reported error did not establish that the mount was writable. This successor accepts only the exact original attach mountpoint/device, then requires diskutil to report the same `MountPoint` and `DeviceNode`, `BusProtocol=Disk Image`, and all three writable fields as Boolean false. Missing, true or non-Boolean writable values are refused. If `ReadOnlyVolume` is present, it must be Boolean true and cannot contradict those fields. These are this diagnostic's explicit admission conditions, not a claim that every macOS version reports this schema.

The original attach's confirmed owned device is recorded before the read-only validation, so a later failure can attempt the existing ordinary detach of only that device. Unknown attach ownership is never adopted; held metadata owners still prevent detach, and no force or extra retry is added. The identity snapshot does not itself prove read-only validation or closure. Only an actual successful detach receipt can establish ordinary closure; runner teardown cannot. Offline tests using recorded plist fixtures validate the pure selectors only and are separate from any future real mount or vendor CLI result.

Before the finder runs, every production default candidate is inventoried without executing it. If another earlier real candidate exists, default discovery stops. Only the explicit `allow_custom_path_diagnostic` dispatch input can instead admit one strict custom-path probe of the same authentic nested CLI. A custom result is never automatic-discovery proof. At most one real `--version` process can launch across both lanes. No default candidates, execution results, host architecture, clock or product timeout are replaced; the observer forwards real `execFile` arguments/options/callback unchanged and retains the original child. The unchanged five-second/64KiB product deadline applies. A retained close event and exit0 are required; a failure/unclosed owner cannot become PASS or trigger a retry/added kill/PID adoption.

Version processes receive only fresh HOME/CODEX_HOME/tmp, file-only credential configuration and a small allowlisted PATH. The driver does not read or copy user auth/config and supplies no credentials; this configuration isolation is not an OS file-access trace or sandbox proof. No desktop app, account manager, login status, app-server, OAuth browser, model turn or project execution is started. The result proves only its actual recorded lane, vendor cohort and native CLI version. It does not establish Accounts first-launch UI, the exact reporter installation, physical absence of every other CLI, authenticated execution, or issue completion.

Artifacts contain only bounded metadata, source/bundle hash inventories and original-owner journals. Vendor DMG/app bytes and private HOME are excluded. Ordinary detach is limited to the confirmed owned mount, without force. A metadata command that exceeds its soft deadline is held without signals. The workflow's ten-minute host deadline is the only hard outer bound for the overall diagnostic, including DNS, connection attempts and TLS. Host cancellation at that limit is external termination, not evidence that the original child or its standard streams closed, or that the mount was detached cleanly.
