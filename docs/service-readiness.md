# 서비스 준비 상태 관찰

프로젝트 뷰어의 **서비스 준비 상태**에서 URL을 입력하고 **지금 검사**를 누른다. 이 컴퓨터가 쿠키·인증 헤더 없이 보내는 GET의 HTTP 상태, 검사 시각, URL을 프로젝트 에이전트 실행 기록과 함께 표시한다. HTTP 검사는 수동이며 에이전트 상태 조회만 패널을 펼친 동안 갱신한다.

2xx는 HTTP 응답을 받았다는 뜻이다. 로그인 뒤 사용 흐름이나 데이터 저장 성공까지 증명하지 않는다. 3xx는 따라가지 않고 원래 응답을 표시한다. HTTP 오류 응답, 연결 거절, 5초 제한 시간을 구분한다. SSH 프로젝트 URL도 이 컴퓨터 관점의 요청이므로 SSH 호스트 내부 연결을 검사한 결과로 해석할 수 없다.

로컬 프로젝트에서 선택한 상대 경로 파일은 프로젝트 폴더 안의 현재 바이트를 SHA-256으로 비교한다. 기존 파일 읽기의 경로·심볼릭 링크·일반 파일·20 MB 제한을 적용한다. **비교 파일**은 실행 배포 파일의 증명이 아니다. 현재 기능은 수신 포트의 PID, 프로세스 시작 명령, 실제 실행 파일과 비교 파일을 연결하지 않으므로 **실행 배포 파일: 미확인**을 유지한다. SSH 파일 비교는 제공하지 않는다.

결과는 프로젝트 화면을 닫거나 앱을 종료하면 보존되지 않는다. URL·프로젝트 연결·비교 파일이 바뀌면 이전 성공을 재사용하지 않는다. 검사 중 대상이 바뀌었다가 돌아와도 늦은 응답을 폐기한다. 저장 형식과 기존 백업 자료는 변경하지 않는다.

서비스 시작·복구·자동 재시작은 제공하지 않는다. 로컬 CLI의 정상 완료는 서비스 종료를 뜻하지 않는다. 취소 시 POSIX 프로세스 그룹에 보내는 종료 신호는 같은 그룹의 서비스에도 전달될 수 있고, Windows는 프로세스 트리를 종료한다. 별도 실행한 서비스의 유지 여부는 시작 도구와 운영체제에 달려 있다. 앱·운영체제 종료, 호스트 재부팅, SSH 단절 후 유지는 이 관찰 기능이 보장하지 않는다.

이 기능은 #15의 관찰 표시를 위한 1단계다. 과거 `ERR_CONNECTION_REFUSED` 제보의 원인은 당시 프로세스·호스트 기록이 없어 미확인이다. 새 합성 재현 결과로 과거 원인을 확정하거나, 실행 배포 파일 연결과 SSH 호스트 관점을 검증한 것으로 처리하지 않는다.

검증: `node --test tests/service-readiness.test.cjs tests/main.test.cjs`, `npm run build`, `npm run test:service-readiness`. UI 검사는 격리한 합성 CLI와 loopback HTTP 서버로 실행하며 실제 AI·계정·SSH 자원을 사용하지 않는다.
