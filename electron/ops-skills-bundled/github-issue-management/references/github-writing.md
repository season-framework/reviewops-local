# GitHub 본문 작성 양식

해당 이슈를 이해하고 동작을 확인하는 데 필요한 항목만 사용한다. 빈 항목을 채우기 위한 내용이나 사진을 추가하지 않는다. UI 문제에 필요한 사진과 개발 결과 댓글의 사진·시나리오·세부 결과는 생략하지 않는다. 아래 예시의 대괄호는 실제 값으로 바꾸고 게시 전에 모두 제거한다.

## 새 이슈

```markdown
## 문제

- [어떤 상태에서 어떤 조작을 하면 무엇이 잘못되는지]
- [사용자에게 발생하는 구체적인 불편 또는 작업 손실]

## 재현

- 환경: [버전·운영체제·소스 실행/배포 앱·필요한 설정]
- 초기 상태: [선택한 대상과 저장된 자료 등 재현에 필요한 상태]

| 단계 | 조작 | 실제 결과 |
| --- | --- | --- |
| 1 | [직접 수행한 조작] | [관찰한 결과] |
| 2 | [다음 조작] | [문제가 나타난 상태] |

## 화면

### 1. [초기 상태 또는 조작 단계]

![1. 실제 단계 제목](검증한-이미지-URL)

- ① [사진 속 위치와 내용].

### 2. [문제가 나타난 단계]

![2. 실제 단계 제목](검증한-이미지-URL)

- ① [문제가 나타난 위치], ② [함께 남아 있는 상태].

## 기대한 동작

- [같은 조건에서 수행되어야 하는 구체적인 동작]

## 관련 코드

- [직접 읽은 코드와 연결된 파일 링크. 원인을 단정하지 않음]
```

코드 위치가 확인되지 않았다면 관련 코드 항목은 넣지 않는다. 직접 재현하지 못한 사용자 제보는 ‘제보 내용’으로 표시하고 작성자가 실행한 것처럼 쓰지 않는다. 단순한 UI 문제에는 같은 의미의 장면을 여러 장 붙이지 않는다.

## 개발 결과 댓글

```markdown
## 개발 결과

- [요구한 동작과 실제 바뀐 동작]
- [예외 처리·자료 유지·복구 등 해당 이슈의 세부 수정]
- 적용 코드: [원격에 존재하는 전체 SHA의 커밋 또는 파일 링크]

## 조작과 검사 결과

- 환경: [검사한 버전·운영체제·소스 실행/배포 앱]
- 검사 조건: [실제 실행/시험용 응답/의도적으로 발생시킨 오류 등]

| 항목 | 조작 | 예상 동작 | 실제 결과 |
| --- | --- | --- | --- |
| [ID 또는 짧은 이름] | [초기 상태 → 조작 → 다음 조작] | [확인할 동작] | **[실제 판정]**<br>[실제로 나타난 상태·값] |

## 조작 화면

### 1. [조작 이전 상태]

![1. 실제 단계 제목](검증한-이미지-URL)

- ① [처음 선택한 대상·입력·설정].

### 2. [조작 후 결과]

![2. 실제 단계 제목](검증한-이미지-URL)

- ① [동작 결과], ② [유지되어야 하는 자료 또는 상태].

## 추가 검사

- [해당 변경을 검사한 명령 또는 검사명]: [실제 결과].
```

판정은 실제 결과 셀의 첫 줄에 `**통과**<br>`, `**오류 발견**<br>`, `**미실행**<br>`, `**기능 미제공**<br>` 중 실제 검사 결과에 맞게 표시한다. 사진은 표와 분리한 화면 흐름에 배치하고 조작 단계와 같은 순서로 연결한다.

추가 검사가 없으면 해당 항목은 생략한다. 사진 수는 동작 설명에 맞춘다. 한 장으로 충분한 경우 한 장을 사용하고, 선택·실행·실패·복구의 관계가 필요한 경우 장면을 추가한다. 성공 화면만으로 실패 뒤 복구, 업데이트 뒤 자료 유지, 여러 창의 독립 동작을 설명하지 않는다.

UI가 없는 기능의 사진 제목은 ‘서비스 요청·응답’, ‘종료 후 다시 연결한 결과’, ‘명령 실행 결과’처럼 실제 화면의 종류를 밝힌다. 로그 사진에는 관련 명령·입력·결과가 함께 보여야 하며 원본 텍스트 출력도 보관한다. 글자가 작으면 전체 화면과 필요한 부분의 확대 화면을 함께 사용한다. 이슈와 무관한 전체 검사 합계 화면은 개발 동작의 대체 사진으로 사용하지 않는다.

## 게시 전후 점검

- 모든 사진과 검사 기록의 대상·시점·조건이 설명과 일치하는지 대조.
- 통과·오류·미실행·미제공과 기능 오류·사용성 불편을 구분.
- 사진의 전체 창·번호·상자·설명과 민감 정보 노출 여부 확인.
- 기존 댓글의 작성자·ID·본문 재조회, 관련 링크 유지, 중복 여부 확인.
- GitHub 미리보기의 실제 이미지 표시·접근 확인 후 영구 첨부 URL로 게시.
- 게시 후 본문 재조회와 GitHub 페이지의 이미지 표시 확인.

짧은 보고 문장으로 작성한다. ‘현재 확인’, ‘근거’, ‘기준’, ‘참고자료’, ‘축’, ‘n가지 ○○’처럼 사용자가 피하도록 지정한 표현을 제목·설명에 넣지 않는다. 다만 실제 UI 라벨이나 외부 문서를 정확히 인용해야 하는 경우에는 뜻을 바꾸지 않고 인용 범위를 분명히 표시한다. 문구 점검 결과는 최종 응답의 체크리스트로 보고한다.
