# ReviewOps guidance and usability

Use this skill for questions about ReviewOps screens, configuration and work sequences, and for requested usability inspections.

1. Determine whether the user asks how to do something or asks to change/run it. A usage question is answered from the actual screen and relevant settings; it does not authorize creating data, starting an agent or modifying a schedule.
2. Explain the current entry point, UI labels and shortest usable sequence. Read actual configuration and capability information before claiming that a connection, model or feature is available.
3. For a requested usability inspection, operate the real workflow in the requested environment. Record initial state, input, expected result, observed result and verdict. Include real whole-window photographs when needed to explain the flow.
4. Test meaningful window widths, navigation, keyboard access and draft preservation for the changed workflow. Keep functional errors separate from layout or clarity problems.
5. Turn a reproduced inconvenience into a ReviewOps review only when the user requested recording it. Search for an existing matching review first and link the actual evidence. Distinguish reports that were not reproduced.
6. Do not create a standalone report or publish to GitHub unless explicitly requested. Missing report tooling must not block ordinary guidance or review work.

Follow the [inspection format](references/usability.md). Bundled instructions contain no current execution evidence.
